## 0. 立项前提

已经有的底盘：

- **萨尔浒**（事件切片，切片 A）+ **开原**（县级 LOD 切片，切片 B）
- 二者**共用同一份真实 ASTER 地形**（`data/terrain/liaodong_grid.json`，97×67 网格），投影基准完全一致
- 四层证据物理隔离：`record` / `scholarship` / `inference` / `gap`

- 三方史料靠 `source_support`/`distance_label`/`layer`/`geographic_origin` **派生**，不手动贴立场标签
- 已有 `terrain_model.py`：Tobler 徒步函数 + 成建制部队折减，可算"史料说几日行军几百里，地形上可能吗"

本路线图目标：用约 **12 小时连续工作**，把项目从"两个漂亮切片"推进到"可演示、可众包、可扩展"的沙盘 v0.3。

## 1. 权限边界（已确认：零额外权限）

| 可用（无需授权） | 不可用（需另行授权） |
|---|---|
| 本地文件读写 | 任何外部账号 API / 付费数据源 |
| 联网检索（WebSearch·WebFetch，本就可用） | 需授权的 MCP 连接器（当前全部 disconnected） |
| 隔离 venv 内纯计算库（lunardate/borax 已装，仅支持 1900+；1619 农历改用联网锚点） | **GitHub 开源推送（需你的仓库 + auth）** |

唯一需要你后续点头的是把代码/数据推到 GitHub 开源——我不会擅自执行，留到收尾你拍板。

已踩的坑：
- `sxtwl`（寿星天文历，架构纲要推荐）在 Python 3.13 无预编译 wheel，需 Rust 编译，放弃。
- `lunardate` / `borax` 均只支持公元 1900–2100，覆盖不了万历四十七年（1619）。
- 对策：1619 农历→公历的**锚点**用联网检索拿带出处的二手值（仍 `paraphrase_unverified`）；**区间**（六月初十→六月十六 = 6 天）本地可验证，不依赖转换器。

### Phase 1 · 地形工程本地化（2h）— 计算型，permission-free　【进行中】
把"史料说几日行军几百里，地形上可能吗"做成可复用、可扩展的分析器。
- 新增 `tools/route_strain.py`：复用 `terrain_model.py`，加载开原/萨尔浒地名，定义 `route_kaiyuan`（赫图阿拉→开原，nodes 用 K008 出兵日 / K009 陷落日）
- 输出开原地形紧张度报告，与 `route_jin`（萨尔浒·后金主力）对照
- 预期：开原路紧张度偏高（"值得复查"），呼应"局部优势是空间距离累积"这一毛泽东式直觉
- 产物：`data/kaiyuan/route_kaiyuan.json`（路线 + 计算报告），供 UI 后续接线显示

### Phase 2 · 三方史料共振引擎（2.5h）— 计算型 + 数据
把"立场靠来源派生，不需独立标签"变成一个**可量化的共振度**。
- `tools/resonance.py`：按事件聚合 明/清/朝鲜 断言
  - `coverage` 覆盖度 = 有几方对该事件有断言
  - `divergence` 分歧度 = 同 (subject,predicate) 不同值的组数（复用 `build_conflicts` 思路）
  - `gap` 缺口度 = 该事件下 `gap` 层断言数
  - `resonance = f(coverage, 1−divergence, 1−gap)`
- 对 `event:kaifa`（开原陷落）与萨尔浒关键事件跑报告
- UI：右栏新增"共振"标签，用色阶显示每事件三方闭合程度
- 原则：**呈现差异不是裁决对错**，与架构纲要一致

### Phase 3 · 缺口闭环（计算型）（1.5h）— permission-free 快速胜利
- **K024 朔闰换算**：六月初十→六月十六区间（6 天）本地验证；公历锚点用联网检索带出处值，更新断言（仍 `paraphrase_unverified`）

### Phase 4 · 多切片导航枢纽（2h）

## 3. 风险与取舍

- 不依赖外部付费/授权数据 → Phase 5 史料以 WebSearch 可得的公有领域材料为限
- 三方共振是"呈现差异"不是"裁决对错"，与架构纲要一致
- 所有 AI 推演/意译内容走 `quote_status = paraphrase_unverified / generated`，UI 显式标注，AI 层可一键关闭
- 1619 农历换算受库限制，公历锚点采用联网二手值并显式降级，不伪造精度
