## 二、P0-A：v0.194 PRC epoch（可直接开跑）

规格、命令、八步流水线全部在 `HANDOFF-2026-09-09.md` 第四节，**照抄即可**，无需再探索。

两个必须守的口径：

1. **诚实口径**：PRC 场景用公开权威史志／工程志／公报口径，不杜撰 per-place 坐标；无真实经纬就 OFF_GRID 挂 banner。
2. **反事实要有意义**：PRC 工程的 what-if 分支建议设为「未建成／延后十年」这类真实可辩的对照，
   不要设成纯粹的阻力数值游戏——拉窗后偏离要真能过 G2（≥0.1），否则宁可调窗口也不硬抬 base_rate。

## 三、P0-B：县级密度破零（这是真正的主战场，但需要想清楚再动）

### 为什么不能盲跑 LLM

县级场景的命根子是**真实坐标**。LLM 编出来的经纬度会让 county.html 的地形取样、OFF_GRID 判定全部失真，
而且**混入后不可逆**——这直接违反项目的诚实边界原则。所以这条路**不能**用 world-gen 批量生成。

### 建议做法（三阶段）

**阶段 1 · 摸底（只读，不改数据）**
- 盘点现有 440 场景里 `places` 带真实经纬度的有多少、分布在哪几个省。
- 确认 `county.html` + `demo/terrain/china_coarse.js` 在真实县级坐标下的取样表现（截图取证）。

**阶段 2 · 单点试点（1–2 个县，手工考据）**
- 挑**已有史料沉淀**的县做试点，建议从已落地的场景反推：
  - 河南林县（红旗渠，v0.194 第 3 号主题就在那）→ 工程 + 地理双维天然齐全；
  - 或山西/陕西一个有明清方志的县。
- 按「六文件 + 一条注册条目」范式手工补齐，验证：`assertions.jsonl` / `places.json`（真实经纬度）/
  `sources.json` / `events.json` / `control.json` / `sim_config.json` + scenes.json 注册。
- 验收：gates 35/35 + G2 过闸 + CDP 截图能看到真实地形（不是 OFF_GRID banner）。

**阶段 3 · 模板化复制**
- 试点跑通后，把「县名 → 坐标 → 六文件骨架」抽成脚本，但**坐标必须来自外部权威源人工确认**，
  不接受 LLM 凭空生成。一次 5–10 个县，人工复核后再入库。

### 判断标准（什么时候算破零成功）

不是"加了 N 个县"，而是：**随机抽一个中国县名，系统能不能给出一张不撒谎的地图**。
试点 1–2 个县跑通 = 范式成立；在此之前不要批量。

## 四、P1：74 个 None-province 债

- **半自动**：用场景已有 `places` 名称 → 现代省码映射（`tools/ingestion/province_map.py`）。
- **必须人工复核**：映射不出的（跨国、跨省、历史地名）保持 `None`，**不要猜**。
- 目标：先把可映射的清掉，剩下列成清单摆给用户，由他决定是否逐个考据。

---

## 五、明确不做（替你守住边界）

1. **不批量 LLM 生成县级坐标** —— 会不可逆地污染诚实边界。
2. **不自动填 None-province** —— 猜错的省比空着更坏。
3. **不给确无技术维的场景硬塞 dim2 断言** —— 覆盖率数字好看，数据本身变假。
   （v0.192 vs v0.193 已经证明：加新场景 +1.0pp，诚实回填 +9.4pp。剩下的靠新场景堆，性价比极低。）
4. **不为凑 epoch floor 加没有独立史料的场景** —— floor-8 已经收口，再往上要有史料理由。
