## 二、P0-A：v0.194 PRC epoch（已完成）

✅ 全部 10 场景入库（commit `8319fa8`）：成渝铁路/武汉长江大桥/红旗渠/两弹一星/南京长江大桥/袁隆平/深圳特区/青藏铁路/三峡/神舟。
gates 35/35、G2 177/177、test_simulate 79 ok、CDP 10/10。

**P0-B：county kind 扩地域（取消 P0 县级破零描述，详见 SURVEY）**

摸底已揭示 county kind 24 个场景 96% places 有真实经纬度。**真正缺口是广地域覆盖**：
- 已有：liaoning 13 / overseas 2 / henan 1 / shaanxi 1 / song/tang 7
- 空白：四川/闽粤/云贵/两淮/江南/华北……**约 20+ 省尚未被 county kind 触及**

**建议三阶段**：

**阶段 1（已完成）：只读摸底**——详见 `SURVEY-2026-09-09-county-geo.md`。

**阶段 2：手工单县试点**——选 1 个空白省份（如四川或福建），按 v0.18x 辽东 county 模板（六文件 + scene entry + places.json 真实经纬度）手工建 1 个场景，验证 county.html 在新省真实经纬度下渲染正常。**坐标必须外部权威源人工确认**（CHGIS / 民政部 / 中国历史地名词典 / 天地图），不接受 LLM 凭空生成。

**阶段 3：模板化复制**——提取「县名 + 史料 + 经纬度（六文件骨架）」脚本，**坐标从已建库的权威源表查**，不接受 LLM 凭空生成。一次 5–10 个县，人工复核后入库。

**判断标准**（什么时候算"县域广覆盖"完成）：
1. 随机抽一个朝代 + 一个现代县名，系统能不能渲染 county.html 地图
2. county kind 是否覆盖 ≥10 个省份（目前 4 省：liaoning/henan/shaanxi/overseas）
3. scale_tier=county **不需要**单独类型（county kind + operational scale 已能渲染）

**P0-C：engineering/tech/thought 经纬度补强**

- 这三类 kind 总 place 441 个，缺经纬度 295 个（缺 67%）
- 哪些是「真应该补」（场景有真实地名）：用 `places.json` 检索「含 lat/lon 缺」的条目 → 查 CHGIS/民政部/中国历史地名词典
- 哪些是「就该空」（场景是抽象概念）：如「道」「理」「气」等抽象哲学概念的 place 字段，本来就不应有经纬度
- **不能用 LLM 补**——必须人工确认每条
- 工作量大、ROI 不高；建议先做阶段 2（county 扩地域），P0-C 视阶段 2 结果再定

## 五、明确不做（替你守住边界）

1. **不批量 LLM 生成县级坐标** —— 会不可逆地污染诚实边界。
2. **不自动填 None-province** —— 猜错的省比空着更坏。
3. **不给确无技术维的场景硬塞 dim2 断言** —— 覆盖率数字好看，数据本身变假。
   （v0.192 vs v0.193 已经证明：加新场景 +1.0pp，诚实回填 +9.4pp。剩下的靠新场景堆，性价比极低。）
4. **不为凑 epoch floor 加没有独立史料的场景** —— floor-8 已经收口，再往上要有史料理由。
