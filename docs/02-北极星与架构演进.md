# 北极星与架构演进

> 配套文档：[`03-通用世界模型-schema.md`](03-通用世界模型-schema.md)（具体文件结构与时序约定）
> 本文回答"我们要去哪、为什么现在的代码不是废稿、还差哪几层"。

## 0. 一句话

我们把"有文字记载的人类经验"当成可计算的对象：导入**文字资料 + 地图**，系统自动呈现一个**可质证、可演化**的世界；这个世界可以是真实的某段历史，也可以是一本玄幻小说，甚至是"假如当年当事人做了另一个选择"的反事实分支。

明末清初的辽东，只是这个系统的**第一个参考实现 / 招人诱饵**，不是终态。

## 1. demo 不是废稿

v0.6 已经沉淀出一套抽象，恰好就是通用系统需要的建模基底：

- **断言驱动**：每条"说法"是带层级的独立事实（史料 / 考据 / 推论 / 缺口）。
- **立场靠来源派生**：立场不手工贴，由 `source.party → 词表 → 分桶` 自动算。
- **缺口是一等公民**：证据不足 / 作者没写明的，显式留成"待补"而不是偷偷填。
- **诚实边界**：没有依据就不伪造（地形不编高程；虚构世界则区分"有据几何"与"生成几何"）。
- **声明式容器**：一个切片 = 一个目录 + 一条注册，零前端改动即可上线。

这套机制对"真实史料"和"虚构小说"是**同一个图模型**，差异只在两处：立场的语义、以及是否叠加"演化层"。所以辽东 demo 是雏形验证，数据沉淀和招人都有长期价值。

## 2. 北极星三支柱

### 2.1 全时段 · 全地域
人类有文字记载的**全部时期 + 全部地区**。用户导入"文字资料 + 地图"，系统自动把这些资料结构化并呈现（谁、在哪、发生了什么、各方怎么讲、证据够不够）。辽东是其中一个 world。

### 2.2 任意文字 → 一个世界
小说（含玄幻）、史料、设定集、口述整理……任何文本都能作为"世界种子"：抽取出实体（地点 / 人物 / 阵营）、关系、事件、时间线，必要时再接一份地图。产出物与 2.1 同构——都是"世界"。

### 2.3 世界自由演化 / 反事实模拟
给一个世界的**初始条件**，让它在规则（或 agent / LLM 推演）驱动下自行向前演化；
同一引擎可服务**历史假设**：在某个历史节点，若当事人做了另一个选择，后续走向如何。
→ 2.2 产出"世界"，2.3 让"世界"动起来并产生分叉。

## 3. 现有基底为何能复用（核心抽象对照）

| v0.6 机制 | 史料世界语义 | 放大到北极星后 |
|---|---|---|
| 断言 claim + layer | 一条史料说法 | 任意世界的一条事实 / 设定 |
| 立场靠来源派生 | 来源方 = 明方 / 清方视角 | 小说 = 叙述者 / 阵营视角；同一引擎 |
| 缺口是一等公民 | 证据不足处（学术诚实） | 作者没写明的设定（演化层补全或留白） |
| 诚实边界 | 网格外不编地形 | 虚构世界：区分"有据几何"与"生成几何" |
| 声明式 slice | 一个县 = 一个切片 | slice 泛化为 **world**（地理的或虚构的） |

## 4. 架构分层：现有 → 缺失

```
[呈现层]  枢纽地图 / 史料卡片 / 图层 / 时间轴     ← 已有，需泛化到多 world
   ↑
[表示层]  断言图模型（sources/places/persons/events/edges/assertions） ← 已有，需 world 级隔离
   ↑
[时间层]  分支时间线（alt-history / 演化分叉）     ← 缺失
   ↑
[抽取层]  ingestion：文本(+地图) → 结构化世界模型  ← 缺失（最硬，需 LLM/NLP）
   ↑
[地图层]  地图导入（图片/GeoTIFF/坐标，动态投影）  ← 部分有（已是动态并集边界）
   ↑
[词汇层]  vocab 按 world 隔离（parties/factions/sources） ← 缺失（现为全局明清词表）
   ↑
[演化层]  simulation：规则/agent/LLM 驱动世界演化   ← 缺失（最研究向）
```

### 4.1 表示层（已有，泛化）
`data/<slice>/` 六件套 → 泛化为 `worlds/<world_id>/`；"scene" 概念升级为 "world"。详见 schema 文档。

### 4.2 ingestion 抽取层（缺失，最硬）
现在靠 DH 人手整理。通用目标要"导入即呈现"，需要 LLM/抽取管线把文本变成结构化断言。
这是真实工程 + NLP 问题，也是招人里最该优先补的"程序 / NLP"角色。
接口约定见 schema 文档 §7。

### 4.3 地图导入（部分有）
现在地形写死 ASTER 辽东网格。要能接用户地图（图片 / GeoTIFF / 坐标）。
`hub.js` / `county.js` 已改成动态并集边界，是好的起点；下一步是接受"用户提供的地图即 geo_ref"。

### 4.4 vocab 按 world 隔离（缺失）
现在 `data/vocab.json` 是全局明清党派。每个 world 须自带 `vocab.json`
（自己的 parties / factions / sources / 立场分桶规则）。**单一真值原则不变，作用域降到 world 级**。

### 4.5 分支时间线（缺失）
现在事件只是零散年份字符串。反事实需要"某节点分叉出 alt-history"的树模型
（`timeline.json`：节点带 `parent`，分支带 `alternative_choice` 与 `label`）。

### 4.6 simulation 演化引擎（缺失，最研究向）
规则 / agent / LLM 推演驱动世界向前走、产生分叉。这块最不确定：
建议先用"轻量规则 + LLM 推演下一步"的混合原型探路，不急着上重架构。
配置见 schema 文档 §6 `sim_config.json`。

## 5. 诚实原则在通用世界的映射

| 原则 | 史料世界 | 虚构 / 模拟世界 |
|---|---|---|
| 立场靠来源派生 | 来源方视角 | 叙述者 / 阵营视角 |
| 缺口是一等公民 | 证据不足，显式留白 | 作者未写明 / 演化未覆盖，显式留白 |
| 不伪造 | 不编高程 | 区分"有据几何"与"生成几何"，生成部分标注 |
| 可质证 | 引文 + 来源可追 | 设定出处（哪一卷 / 哪段原文）可追 |

核心不变：**只投影、不裁判；没依据就标出来，而不是替用户做决定。**

## 6. 分阶段路线图

- **M1 参考实现（已完成 v0.6）**：辽东 14 切片、断言图模型、诚实边界、四闸门、CI、招人物料。
- **M2 通用 world 模型**：落地 `worlds/<id>/` schema（本文配套文档），把辽东迁移为第一个 world；vocab 按 world 隔离；门户支持多 world 切换。
- **M3 ingestion 原型**：拿一段真实文本（史料或小说）跑通"文本 → 结构化世界模型 → 呈现"；先半自动（LLM 抽 + 人校验），再逐步自动化。
- **M4 地图导入**：接受用户地图，动态投影通用化。
- **M5 分支时间线**：支持 alt-history 展示。
- **M6 演化引擎**：轻量规则 + LLM 推演的最小可用演化 / 反事实原型。

## 7. 对协作的影响（招人）

- **数字人文 / 史料核验**：仍要，且是关键质量守门人（校验抽取结果）。角色从"主要劳动力"变为"质检 + 补缺口"。
- **视觉 / 界面设计**：仍要，且随多 world、时间轴、演化可视化而更重要。
- **程序 / 架构（NLP / LLM 抽取）**：从"暂缓"变**关键**——ingestion 是实打实的工程问题。
- **模拟引擎方向**：M5/M6 起需要，可先物色、不急于全职。

## 8. 风险与未决

- ingestion 的抽取质量高度依赖 LLM；"导入即呈现"先做到"半自动 + 人校验"更现实。
- 演化引擎是开放研究问题，M6 不承诺重架构，先探路。
- 虚构世界的"立场 / 诚实"语义需要和产品定位对齐（娱乐向可降低质证强度，学术向保持）。
- 多 world 的版权 / 数据授权：真实史料受版权数据集约束（CHGIS/CBDB 仅适配器 + 运行时下载）；虚构世界需注意原作者授权。
