这个项目在坚持什么

不是又一份「标准叙事」。四条工程主张决定了它和所有历史可视化产品的分界线——也决定了合作者能往哪里使劲。

立场靠来源派生

每条断言的「明方 / 清方 / 朝鲜 / 综述考订」立场，不是人手贴标签，而是由 source.party 经受控词表自动派生。改一处词表，全站共振度自动重算。

缺口是一等公民

「我们不知道」和「我们知道」同等重要。每条史料缺口都写成可认领的「研究线索」，挂给合作者去补——这正是本页下方 33 条线索的来历。

断言驱动，不裁判

内核只投影、不裁判。真伪由读者的「来源采信开关」决定。关掉二手综述，看哪些结论会塌——这是对来源依赖度的可视化压力测试。

叠在真实地形上

所有地点投影到 ASTER 真实高程网格（辽东 122–126.8°E，40–43.3°N）。城、关、河、边墙都在你能查到的坐标上，不是示意图。

它到底怎么算出来的

对新人（尤其数字人文与美工）最关键的一节：内核不裁判，只把下面这条流水线投影到真实地形上。看懂它，你就知道自己的活会落在哪一环。

断言是原子单位 数据

每条断言 = 主语 + 谓词 + 取值 + 来源 + 层级。空引文、空值会被 lint 当 bug 抓出（E07/E10），因为下游共振度会据此算错。

立场靠来源派生 派生

source.party 经 data/vocab.json 受控词表映射成 明方 / 清方 / 朝鲜 / 综述考订。改一处词表，全站共振度自动重算——不手动贴标签。

共振度 = 多方共识 算法

同一结论被越多不同立场的史料支持，共振度越高。这正是「历史由多种因素导致」的可视化：高共振 = 多派都这么说。

冲突自动成组 算法

同一 (主语, 谓词) 出现不同取值，内核自动聚成冲突组，不依赖人手标注。关掉某方来源，看哪些结论会塌。

怎么跑起来

纯静态 + Python 守门工具链，无前端框架、无数据库。本地看成品只需一个静态服务器。

# 1. 克隆
git clone https://github.com/davidyue-0510/history-in-my-hand.git
cd history-in-my-hand

# 2. 看成品（任意静态服务器）
python -m http.server 8787
# 打开 http://localhost:8787/demo/portal.html

# 3. 改了数据后，过四道闸门（或一条命令全跑）
python tools/gates.py        # lint + test + leads + build 一气呵成
# 拆开看：
python tools/lint.py         # 守门员：数据完整性
python tools/test_assertions.py  # 不变量回归
python tools/leads.py        # 重算研究线索
python tools/build.py        # 重编译 demo/data.js

三个角色的第一条命令都一样

区别只在改完之后碰哪类文件。守门工具链会拦住「空引文」「分类散落」「时间轴脱钩」这类会静默污染下游计算的错误——所以任何提交都先过 lint。

想认领研究线索？直接去 data/<切片>/assertions.jsonl 加一条 layer:"gap" 带 lead 块的断言，tools/leads.py 会自动把它收进总览。
